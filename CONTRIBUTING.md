# Contributing to Nexora

Nexora is a **fork of Vencord**. Most contribution norms for plugins and patches follow the upstream project.

- Architecture and policy: [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md)
- Installation: [docs/INSTALLATION.md](./docs/INSTALLATION.md)
- Nexora plugins: put new official features in `src/nexoraPlugins/`, not by rewriting unrelated upstream plugins
- Custom local experiments: `src/userplugins/` (gitignored)
- Upstream plugin API docs: https://docs.vencord.dev/

## Pull requests

1. Prefer small, reviewable changes
2. Run `pnpm build` and `pnpm testTsc` before opening a PR
3. Disclose AI assistance if used; do not submit unreviewed AI slop
4. Keep GPL-3.0-or-later headers on new source files
5. Do not commit secrets, tokens, or personal Discord message logs

## Merging upstream

```bash
git fetch upstream
git merge upstream/main
# resolve conflicts; prefer keeping nexoraPlugins / docs / NOTICE intact
```

# Upstream: Contributing to Vencord

The following guidance is retained from Vencord and still applies to shared upstream code.

Vencord is a community project and welcomes any kind of contribution from anyone!

We have development documentation for new contributors, which can be found at <https://docs.vencord.dev>.

## AI Policy

<!-- This section was mostly copied from Ghostty and adapted for Vencord, credits to Mitchell Hashimoto -->

Vencord has strict rules for AI usage:

- **AI slop will result in a block**. If code or text you submit is clearly generated by AI without human review and cleanup, you will be blocked from contributing to the project. Examples of slop include overly verbose text, unnecessary comments, overcomplicated code, failure to follow project conventions, and other signs of minimal human involvement.

- **All AI usage in any form must be disclosed.** You must state the tool you used (e.g. Claude Code, Codex) along with the extent that the work was AI-assisted.

- **The human-in-the-loop must fully understand all code.** If you can't explain what your changes do and how they interact with the greater system without the aid of AI tools, do not contribute to this project.

- **Don't post AI generated texts in issues, discussions or PRs**. AI is very good at being overly verbose and including noise that distracts from the main point. You can use AI to assist you, but you must trim it down and ensure it is concise and relevant.

## How to contribute

Contributions can be sent via pull requests. If you're new to Git, check [this guide](https://opensource.com/article/19/7/create-pull-request-github).

Pull requests can be made either to the `main` or the `dev` branch. However, unless you're an advanced user, I recommend sticking to `main`.
This is because the dev branch might contain unstable changes and be force pushed frequently, which could cause conflicts in your pull request.

Before working on a major change, I highly recommend opening a feature request for it, making sure to check "I am willing to work on this myself",
so we can discuss before you invest time. Alternatively, you can also do so in our Discord server's development
channels. This saves you a lot of time in case your feature is considered too niche or rejected for any other reason.

## Write a plugin

Writing a plugin is the primary way to contribute.

Please follow the plugin guide at https://docs.vencord.dev/plugins/ and place Nexora-specific plugins under `src/nexoraPlugins/`.
